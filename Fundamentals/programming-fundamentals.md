# Programming Fundamentals - WellDev MCQ Preparation (Ultimate Guide)

WellDev এর মত কোম্পানির Trainee Software Engineer পদের MCQ পরীক্ষায় প্রোগ্রামিং ফান্ডামেন্টালস থেকে প্রচুর 'Predict the output' (আউটপুট কী হবে) এবং কনসেপচুয়াল প্রশ্ন আসে। এই ডকুমেন্টটি একেবারে বেসিক থেকে শুরু করে ইন্টারভিউতে আসা ট্রিকি বিষয়গুলো পর্যন্ত বাংলায় বিস্তারিত কভার করবে।

## ১. Data Types এবং Memory Management (ডাটা টাইপ ও মেমোরি)

যেকোনো প্রোগ্রামিং ভাষায় কাজ করার আগে তার ডাটা টাইপ এবং মেমোরি কীভাবে কাজ করে তা জানা অত্যাবশ্যক।

### ১.১ Primitive vs Reference/Non-Primitive Types
*   **Primitive Types (Value Types):** এগুলো সবচেয়ে বেসিক ডাটা টাইপ (যেমন: `int`, `char`, `float`, `boolean`)। এরা সরাসরি ভ্যালু বা মান ধারণ করে।
*   **Reference Types:** এগুলো সরাসরি ভ্যালু ধারণ করে না, বরং ভ্যালুটি মেমোরির যেখানে আছে তার ঠিকানা (Address/Reference) ধারণ করে। (যেমন: Arrays, Objects, Strings in Java/C#)।

### ১.২ Stack vs Heap Memory (ভেরি ইম্পর্টেন্ট)
*   **Stack Memory (স্ট্যাক):**
    *   এটি খুব ফাস্ট কাজ করে। 
    *   এখানে স্ট্যাটিক মেমোরি অ্যালোকেশন হয় (যেমন লোকাল ভ্যারিয়েবল, ফাংশন কলের ইনফরমেশন)।
    *   স্ট্যাক কাজ করে LIFO (Last In, First Out) পদ্ধতিতে। 
    *   স্ট্যাকের সাইজ লিমিটেড থাকে। ফাংশন বারবার কল হতে থাকলে (যেমন ইনফিনিট রিকার্সন) `StackOverflowError` হয়।
    *   Primitive type এর ভ্যালুগুলো সরাসরি স্ট্যাকে সেভ হয়।
*   **Heap Memory (হিপ):**
    *   এটি স্ট্যাকের চেয়ে তুলনামূলক স্লো।
    *   এখানে ডায়নামিক মেমোরি অ্যালোকেশন হয় (যখন আমরা `new` কিওয়ার্ড ব্যবহার করে অবজেক্ট বা অ্যারে বানাই)।
    *   Reference type এর আসল ডাটাগুলো হিপে সেভ হয়, আর সেই হিপ মেমোরির ঠিকানাটা স্ট্যাকে থাকা ভ্যারিয়েবলে সেভ হয়।
    *   Garbage Collector (জাভা/সি# এর ক্ষেত্রে) হিপ মেমোরি থেকে অব্যবহৃত অবজেক্টগুলো ক্লিয়ার করে।

### ১.৩ Pass by Value vs Pass by Reference (MCQ তে কনফিউজ করার সেরা জায়গা)
*   **Pass by Value:** যখন আপনি কোনো ফাংশনে আর্গুমেন্ট পাঠান, তখন মূল ভ্যারিয়েবলের একটি **কপি** ফাংশনে যায়। ফাংশনের ভেতরে সেই কপিতে কোনো চেঞ্জ করলে বাইরের মূল ভ্যারিয়েবলে কোনো চেঞ্জ হয় না। (Primitive types সবসময় Pass by Value হয়)।
*   **Pass by Reference:** ফাংশনে ভ্যালুর কপি না গিয়ে সরাসরি তার মেমোরি অ্যাড্রেস যায়। ফাংশনের ভেতর চেঞ্জ করলে মূল ডাটাও চেঞ্জ হয়ে যায়। 
*   **ট্রিকি পার্ট (জাভা/জাভাস্ক্রিপ্ট):** জাভা বা জাভাস্ক্রিপ্টে সবকিছুই "Pass by Value"। কিন্তু আপনি যখন কোনো অবজেক্ট বা অ্যারে (Reference type) পাস করেন, তখন মূলত সেই রেফারেন্স বা ঠিকানার **কপিটি** (Value of the reference) পাস হয়। 
    *   *উদাহরণ:* ফাংশনের ভেতর যদি আপনি `array[0] = 5` করেন, মূল অ্যারে চেঞ্জ হবে। কিন্তু আপনি যদি পুরো অ্যারেটিকেই নতুন করে অ্যাসাইন করেন `array = [1,2,3]`, তবে বাইরের মূল অ্যারে চেঞ্জ হবে না।

## ২. Operators (অপারেটরস) - MCQ এর খনি

এমসিকিউ পরীক্ষায় অপারেটর থেকে প্রশ্ন আসবেই। কিছু ট্রিকি অপারেটর নিয়ে আলোচনা করা হলো:

### ২.১ Increment এবং Decrement (`++` এবং `--`)
*   **Pre-increment (`++i`):** আগে ভ্যালু ১ বাড়বে, তারপর সেই লাইনের কাজ হবে।
*   **Post-increment (`i++`):** আগে সেই লাইনের কাজ বর্তমান ভ্যালু দিয়ে শেষ হবে, তারপর ভ্যালু ১ বাড়বে।
*   **MCQ Example:**
    ```java
    int a = 5;
    int b = a++ + ++a; // a++ (b gets 5, a becomes 6) + ++a (a becomes 7, so 7). b = 5 + 7 = 12.
    // আউটপুট: 12
    ```

### ২.২ Logical Operators এবং Short-Circuiting (ভেরি ইম্পর্টেন্ট)
*   `&&` (Logical AND): দুটোর শর্তই সত্য হতে হবে।
*   `||` (Logical OR): যেকোনো একটি শর্ত সত্য হলেই হবে।
*   **Short-Circuit Evaluation:**
    *   `A && B` এর ক্ষেত্রে: যদি `A` মিথ্যা (False) হয়, তবে প্রোগ্রাম `B` কে আর চেকই করবে না (কারণ রেজাল্ট তো এমনিতেই False হবে)।
    *   `A || B` এর ক্ষেত্রে: যদি `A` সত্য (True) হয়, তবে প্রোগ্রাম `B` কে আর চেকই করবে না (কারণ রেজাল্ট তো এমনিতেই True হবে)।
*   **MCQ Trap:**
    ```c
    int i = 0;
    if (1 || (i++)) { 
        // 1 সত্য, তাই (i++) অংশটুকু রানই হবে না Short-circuit এর কারণে।
    }
    // i এর মান 0 ই থেকে যাবে, 1 হবে না।
    ```

### ২.৩ Bitwise Operators (অনেকেই স্কিপ করে, কিন্তু MCQ তে আসে)
এগুলো সরাসরি বাইনারি বিট নিয়ে কাজ করে। 
*   `&` (Bitwise AND), `|` (Bitwise OR), `^` (Bitwise XOR), `~` (Bitwise NOT).
*   `<<` (Left Shift): বিটগুলোকে বামে সরিয়ে দেয়। `x << 1` মানে হলো x কে 2 দিয়ে গুণ করা। `x << 2` মানে 4 দিয়ে গুণ করা।
*   `>>` (Right Shift): বিটগুলোকে ডানে সরিয়ে দেয়। `x >> 1` মানে হলো x কে 2 দিয়ে ভাগ করা।
*   **XOR (`^`) এর জাদু:** 
    *   দুটো সমান নাম্বারের XOR করলে 0 হয়। (`5 ^ 5 = 0`)
    *   যেকোনো নাম্বারের সাথে 0 এর XOR করলে সেই নাম্বারটিই ফেরত আসে। (`5 ^ 0 = 5`)
    *   এটি দিয়ে তৃতীয় কোনো ভ্যারিয়েবল ছাড়াই দুটি ভ্যারিয়েবলের মান সোয়াপ (Swap) করা যায়।

### ২.৪ Modulo Operator (`%`)
ভাগশেষ বের করতে ব্যবহৃত হয়। 
*   নেগেটিভ নাম্বারের ক্ষেত্রে মডুলো: (C/C++/Java তে) `-5 % 2` এর রেজাল্ট হবে `-1` (ভাগের নিয়মে)। 
*   জোড়/বিজোড় চেক করতে: `x % 2 == 0` হলে জোড়।

## ৩. Control Flow (লুপ এবং কন্ডিশন)

### ৩.১ Switch Case
*   **Fall-through:** Switch কেসে যদি কোনো `case` এর শেষে `break;` না দেওয়া হয়, তবে প্রোগ্রাম সেই কেস ম্যাচ করার পর নিচের সব কেসগুলোও রান করতে থাকবে যতক্ষণ না সে একটি `break` পায় বা সুইচ শেষ হয়। একে fall-through বলে। 
*   MCQ তে এই `break` মিসিং দিয়ে অনেক আউটপুট প্রেডিক্ট করতে দেয়।

### ৩.২ Loops (`for`, `while`, `do-while`)
*   `do-while` লুপের বিশেষত্ব হলো - কন্ডিশন মিথ্যা হলেও এর ভেতরের কোড **কমপক্ষে একবার** রান হবেই। কারণ এটি আগে কাজ করে, পরে কন্ডিশন চেক করে।
*   **Infinite Loop (অসীম লুপ):** 
    ```c
    for (;;) { ... } // এটি একটি ইনফিনিট লুপ
    while (true) { ... } // এটিও ইনফিনিট লুপ
    ```

## ৪. Functions এবং Recursion

### ৪.১ Scope (স্কোপ বা কার্যপরিধি)
*   **Global Scope:** ফাংশনের বাইরে ডিক্লেয়ার করা ভ্যারিয়েবল। সব জায়গা থেকে অ্যাক্সেস করা যায়।
*   **Local Scope:** ফাংশনের ভেতর ডিক্লেয়ার করা। শুধু ওই ফাংশনের ভেতরেই চেনা যায়।
*   **Block Scope:** C++, Java, JS (let, const) এর ক্ষেত্রে, `{ }` ব্র্যাকেটের ভেতরে ডিক্লেয়ার করা ভ্যারিয়েবল শুধু ওই ব্র্যাকেটের ভেতরেই থাকে। 
*   **Shadowing:** গ্লোবাল এবং লোকাল ভ্যারিয়েবলের নাম একই হলে, ফাংশনের ভেতর লোকাল ভ্যারিয়েবলটিই প্রাধান্য পায় (গ্লোবালটি ঢাকা পড়ে যায়)।

### ৪.২ Recursion (রিকার্সন)
যখন কোনো ফাংশন নিজেই নিজেকে কল করে।
*   **Base Case:** রিকার্সন থামানোর শর্ত। এটি না থাকলে `StackOverflowError` হবে।
*   **Recursive Step:** প্রবলেমকে ছোট করে আবার ফাংশনকে কল করা।
*   **Tail Recursion:** যখন ফাংশনের একদম শেষ কাজটি হয় রিকার্সিভ কল করা (এরপর আর কোনো ক্যালকুলেশন থাকে না)। কম্পাইলার এটিকে অপটিমাইজ করে লুপের মতো বানিয়ে ফেলতে পারে, ফলে মেমোরি বাঁচে।

## ৫. Exception Handling (এক্সেপশন হ্যান্ডেলিং)

প্রোগ্রাম ক্র্যাশ না করিয়ে এরর সামলানোর উপায়। 
*   `try`: যে কোডে এরর আসতে পারে।
*   `catch`: এরর আসলে কী হবে তা লেখা থাকে।
*   `finally`: **(MCQ তে সবচেয়ে বেশি আসে)** `finally` ব্লকের ভেতরের কোড **সবসময়** রান হবে। 
    *   `try` তে এরর আসুক বা না আসুক।
    *   এমনকি `try` বা `catch` ব্লকের ভেতর যদি `return` স্টেটমেন্টও থাকে, ফাংশন রিটার্ন করার ঠিক আগ মুহূর্তে `finally` ব্লক রান হবেই!

## ৬. Strings (স্ট্রিং)

*   **C-Style Strings:** C তে স্ট্রিং বলতে কিছু নেই, এগুলো মূলত ক্যারেক্টার অ্যারে (Character Array)। এদের শেষে একটি Null Character `\0` থাকতে হয় বোঝানোর জন্য যে স্ট্রিং এখানে শেষ।
*   **Immutability (অপরিবর্তনযোগ্য):** Java, C#, Python, JavaScript এ স্ট্রিং Immutable। এর মানে একবার একটি স্ট্রিং মেমোরিতে তৈরি হলে তা আর চেঞ্জ করা যায় না। আপনি যদি স্ট্রিংয়ে কিছু যোগ করেন (যেমন `str = str + "a"`), তবে আগের স্ট্রিংটি বদলায় না, বরং নতুন একটি স্ট্রিং মেমোরিতে তৈরি হয়।
*   **String Pool (Java):** মেমোরি বাঁচানোর জন্য জাভা একই ভ্যালুর স্ট্রিং বারবার তৈরি না করে একটি "Pool" এ সেভ করে রাখে।

## ৭. Pointers (পয়েন্টার - C/C++ এর জন্য)

যদি পরীক্ষায় C/C++ এর প্রশ্ন থাকে, তবে পয়েন্টার থেকে প্রশ্ন আসবেই।
*   `&` (Address-of operator): ভ্যারিয়েবলের মেমোরি ঠিকানা বের করে।
*   `*` (Dereference operator): পয়েন্টারের ঠিকানায় গিয়ে মূল ভ্যালুটি নিয়ে আসে।
*   **Dangling Pointer:** পয়েন্টার যে ঠিকানাকে নির্দেশ করছিল, মেমোরি থেকে সেই ডাটা মুছে ফেলা হয়েছে, কিন্তু পয়েন্টারটি এখনো ওই খালি ঠিকানার দিকে তাক করে আছে। 
*   **Null Pointer:** পয়েন্টার কাউকে নির্দেশ করছে না (`NULL` বা `0`)।
*   **Wild Pointer:** পয়েন্টার ডিক্লেয়ার করা হয়েছে কিন্তু ইনিশিয়ালাইজ করা হয়নি (গার্বেজ ঠিকানায় তাক করে আছে)।

## ৮. WellDev MCQ এর জন্য বিশেষ টিপস 💡

১. **Dry Run (খাতায় কলমে রান করা):** আউটপুট প্রেডিক্ট করার প্রশ্নে কখনো আন্দাজে দাগাবেন না। লুপ বা ফাংশন দেখলে ভ্যারিয়েবলের একটি টেবিল বানিয়ে খাতা-কলমে লাইন বাই লাইন রান (Trace) করবেন। 
২. **Syntax Errors:** মাঝে মাঝে কোডে ইচ্ছা করে সেমিকোলন (`;`) বাদ দেয়, বা কন্ডিশনের ভেতর `=` (assignment) দেয় `==` (comparison) এর বদলে। (যেমন `if(a = 5)` - এটি সবসময় true হবে কারণ ৫ অ্যাসাইন হচ্ছে, তুলনা হচ্ছে না)। খুব সতর্কভাবে কোড পড়বেন।
৩. **Time Complexity:** প্রোগ্রামিং ফান্ডামেন্টালসের সাথে একটি ছোট কোড দিয়ে জিজ্ঞেস করতে পারে এর Time Complexity কত। (Nested for-loop হলে সাধারণত O(n^2), অর্ধেক করে কমলে O(log n))।
৪. **Edge Cases:** অ্যারের ইনডেক্স আউট অফ বাউন্ড হচ্ছে কিনা (অ্যারের সাইজ ৫ হলে `array[5]` অ্যাক্সেস করলে এরর হবে, কারণ ইনডেক্স ৪ পর্যন্ত)। 

এই ডকুমেন্টটি বারবার পড়ুন এবং বেসিক ক্লিয়ার রাখুন। প্রোগ্রামিং ফান্ডামেন্টালস থেকে প্রশ্নগুলো মূলত আপনার কোডের ফ্লো বুঝতে পারার ক্ষমতা যাচাই করার জন্যই করা হয়। শুভকামনা!
