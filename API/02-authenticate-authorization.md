# Authentication vs Authorization (অথেনটিকেশন বনাম অথোরাইজেশন)

সফটওয়্যার ডেভেলপমেন্ট, সিস্টেম ডিজাইন এবং API সিকিউরিটিতে Authentication এবং Authorization অত্যন্ত গুরুত্বপূর্ণ দুটি কনসেপ্ট। নাম দুটি শুনতে কাছাকাছি মনে হলেও এদের কাজ সম্পূর্ণ আলাদা। ইন্টারভিউতে এই দুটির পার্থক্য খুব বেশি জিজ্ঞেস করা হয়।

---

## ১. Authentication (অথেনটিকেশন - AuthN) কী?

**সহজ কথায়:** "আপনি কে?" (Who are you?) - এটি প্রমান করার প্রক্রিয়াই হলো Authentication।
যখন কোনো ইউজার সিস্টেমে প্রবেশ করতে চায়, তখন সিস্টেম চেক করে দেখে যে ইউজার যা দাবি করছে, সে আসলেই সেই ব্যক্তি কিনা। ইউজারের পরিচয় (Identity) যাচাই করাই এর মূল লক্ষ্য।

### রিয়েল-লাইফ উদাহরণ:
*   **অফিসে প্রবেশ:** আপনি যখন অফিসে ঢোকার সময় গেটে আপনার ID Card বা Fingerprint পাঞ্চ করেন, তখন সিস্টেম বোঝে যে আপনি এই অফিসেরই একজন এমপ্লয়ি। এটি হলো Authentication।
*   **এয়ারপোর্ট:** এয়ারপোর্টে ঢোকার সময় সিকিউরিটিকে আপনার পাসপোর্ট দেখানো হলো Authentication।

### টেকনিক্যাল উদাহরণ (সিস্টেমে যেভাবে হয়):
*   ইউজারনেম এবং পাসওয়ার্ড দিয়ে লগইন করা।
*   মোবাইলে আসা OTP (One Time Password) দিয়ে ভেরিফাই করা।
*   ফিঙ্গারপ্রিন্ট বা ফেস আনলক (Biometric)।

### স্ট্যাটাস কোড (HTTP Status Code):
*   যদি Authentication ফেইল করে (অর্থাৎ আপনি ভুল পাসওয়ার্ড দিয়েছেন বা লগইন করেননি), তখন API **`401 Unauthorized`** স্ট্যাটাস কোড ফেরত দেয়। (এখানে Unauthorized লেখা থাকলেও এটি মূলত Unauthenticated বোঝায়)।

---

## ২. Authorization (অথোরাইজেশন - AuthZ) কী?

**সহজ কথায়:** "আপনি কী কী করতে পারবেন?" (What are you allowed to do?) - এটি নির্ধারণ করাই হলো Authorization।
Authentication সফল হওয়ার পর, অর্থাৎ সিস্টেম যখন চিনে ফেলে আপনি কে, তখন সিস্টেম চেক করে দেখে যে নির্দিষ্ট কোনো কাজ করার বা নির্দিষ্ট কোনো পেজ দেখার অধিকার (Permission/Access) আপনার আছে কিনা।

### রিয়েল-লাইফ উদাহরণ:
*   **অফিসের সার্ভার রুম:** আপনার ID Card দিয়ে আপনি অফিসে (Authenticate হয়ে) ঢুকেছেন। কিন্তু আপনি চাইলেই কি অফিসের মূল 'সার্ভার রুমে' বা 'বস এর রুমে' ঢুকতে পারবেন? না। কারণ আপনার সেখানে যাওয়ার অ্যাক্সেস বা পারমিশন নেই। এই পারমিশন চেক করাটাই হলো Authorization।
*   **এয়ারপোর্ট:** পাসপোর্ট দেখিয়ে এয়ারপোর্টে ঢোকার পর, আপনার টিকিট চেক করে দেখা হয় আপনি কি 'ইকোনমি ক্লাস' এর যাত্রী নাকি 'বিজনেস ক্লাস' এর ভিআইপি লাউঞ্জে যাওয়ার পারমিশন আপনার আছে। এটি Authorization।

### টেকনিক্যাল উদাহরণ (সিস্টেমে যেভাবে হয়):
*   **Role-Based Access Control (RBAC):** সিস্টেমে ইউজারের রোল (Role) সেট করা থাকে। যেমন:
    *   `Admin`: ডাটাবেস ডিলিট করতে পারবে, নতুন ইউজার অ্যাড করতে পারবে।
    *   `Normal User`: শুধু নিজের প্রোফাইল দেখতে এবং এডিট করতে পারবে।
*   আপনি যদি Normal User হয়ে Admin এর কোনো API (যেমন `DELETE /users/10`) কল করার চেষ্টা করেন, সিস্টেম আপনাকে আটকে দেবে।

### স্ট্যাটাস কোড (HTTP Status Code):
*   যদি Authorization ফেইল করে (অর্থাৎ আপনি লগইন করা আছেন, কিন্তু আপনার ওই কাজটি করার পারমিশন নেই), তখন API **`403 Forbidden`** স্ট্যাটাস কোড ফেরত দেয়।

## ৩. Authentication এবং Authorization এর পার্থক্য (সারাংশ)

| বৈশিষ্ট্য | Authentication (AuthN) | Authorization (AuthZ) |
| :--- | :--- | :--- |
| **মূল প্রশ্ন** | আপনি কে? (Identity) | আপনি কী করতে পারবেন? (Permission) |
| **কখন ঘটে?** | সব সময় Authorization এর **আগে** ঘটে। | সব সময় Authentication এর **পরে** ঘটে। |
| **কী যাচাই করে?** | ইউজারের পরিচয় (যেমন পাসওয়ার্ড, বায়োমেট্রিক)। | ইউজারের অ্যাক্সেস লেভেল বা পারমিশন (যেমন Admin/User)। |
| **ব্যর্থ হলে HTTP Code** | `401 Unauthorized` | `403 Forbidden` |
| **ডাটা পরিবর্তন** | এটি ইউজারের তথ্য যাচাই করে, কোনো পারমিশন দেয় না। | এটি সিস্টেমের রিসোর্স ব্যবহারের পারমিশন দেয়। |

---

## ৪. একসাথে কীভাবে কাজ করে? (Workflow Example)

ধরা যাক, আপনি ফেসবুক ব্যবহার করছেন:
1.  **Authentication:** আপনি আপনার ইমেইল এবং পাসওয়ার্ড দিয়ে লগইন করলেন। ফেসবুক সার্ভার চেক করে দেখলো আপনার পাসওয়ার্ড সঠিক। সার্ভার আপনাকে চিনে ফেললো।
2.  **Authorization:** এবার আপনি আপনার বন্ধুর একটি পোস্টে গিয়ে 'Delete' বাটনে ক্লিক করার চেষ্টা করলেন। ফেসবুক সার্ভার চেক করে দেখবে, "এই ইউজার তো লগইন করা আছে (Authenticated), কিন্তু এই পোস্টটি কি তার নিজের? না, এটি তার বন্ধুর পোস্ট।" যেহেতু অন্যের পোস্ট ডিলিট করার পারমিশন আপনার নেই, তাই ফেসবুক সার্ভার আপনার এই রিকোয়েস্টটি রিজেক্ট করে দেবে (Authorization failed - 403 Forbidden)। 

এই দুটি মেকানিজম একসাথে কাজ করেই একটি সিস্টেমকে পুরোপুরি সুরক্ষিত (Secure) রাখে।
