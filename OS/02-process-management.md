# Process Management (প্রসেস ম্যানেজমেন্ট)

Operating System এর সবচেয়ে গুরুত্বপূর্ণ অংশ হলো প্রসেস ম্যানেজমেন্ট। MCQ এর জন্য এই টপিকের খুঁটিনাটি জানা খুব জরুরি।

## ১. Process (প্রসেস) কী?
সহজ ভাষায়, **"A program in execution is called a process."**
আপনার হার্ডডিস্কে রাখা কোড বা গেমটি হলো একটি 'Program' (Passive entity)। কিন্তু যখন আপনি সেটিতে ডাবল ক্লিক করে রান করেন এবং সেটি RAM এ এসে কাজ শুরু করে, তখন সেটি একটি 'Process' (Active entity) এ পরিণত হয়।

---

## ২. Process States (প্রসেস স্টেট - MCQ এর খনি)
একটি প্রসেস তৈরি হওয়া থেকে শুরু করে শেষ হওয়া পর্যন্ত ৫টি প্রধান স্টেটের মধ্য দিয়ে যায়।

1.  **New:** প্রসেসটি মাত্র তৈরি হচ্ছে (এখনো RAM বা Main Memory তে আসেনি, ডিস্কেই আছে)।
2.  **Ready:** প্রসেসটি RAM এ চলে এসেছে এবং CPU তে রান হওয়ার জন্য পুরোপুরি প্রস্তুত হয়ে লাইনে দাঁড়িয়ে আছে। (MCQ: Ready state এর প্রসেসগুলো Main Memory তে থাকে)।
3.  **Running:** প্রসেসটি বর্তমানে CPU তে এক্সিকিউট (রান) হচ্ছে। (সিঙ্গেল কোর প্রসেসরে একবারে মাত্র ১টি প্রসেস Running স্টেটে থাকতে পারে)।
4.  **Waiting / Blocked:** প্রসেসটি রান হচ্ছিল, কিন্তু হঠাৎ তার ইনপুট/আউটপুট (যেমন ইউজারের কীবোর্ড ইনপুট বা ফাইল রিড) এর দরকার পড়ায় সে CPU ছেড়ে দিয়ে Waiting স্টেটে চলে গেছে। I/O শেষ হলে সে আবার Ready স্টেটে ফেরত যাবে, সরাসরি Running এ যেতে পারবে না।
5.  **Terminated:** প্রসেসের কাজ শেষ এবং এটি মেমোরি থেকে মুছে ফেলা হয়েছে।

---

## ৩. Process Control Block (PCB)
প্রতিটি প্রসেসের সমস্ত তথ্য OS একটি ডাটা স্ট্রাকচারে সেভ করে রাখে, যাকে PCB বা Task Control Block বলা হয়। 
**PCB তে কী কী থাকে? (MCQ তে অপশন হিসেবে আসে):**
*   Process ID (PID)
*   Process State (New, Ready, Running ইত্যাদি)
*   Program Counter (পরবর্তী কোন ইন্সট্রাকশনটি রান হবে তার অ্যাড্রেস)
*   CPU Registers এর মান
*   Memory limits
*   List of open files (প্রসেসটি কোন কোন ফাইল ওপেন করেছে)

## ৪. Context Switching (কনটেক্সট সুইচিং)
মাল্টিটাস্কিং OS এ CPU কে একটি প্রসেস থেকে অন্য প্রসেসে বারবার শিফট করতে হয়।
*   **কীভাবে হয়?** যখন CPU প্রসেস P1 কে ছেড়ে প্রসেস P2 তে যায়, তখন OS কে অবশ্যই P1 এর বর্তমান অবস্থা (State) তার PCB তে সেভ করে রাখতে হয়। এরপর P2 এর PCB থেকে তার আগের অবস্থা লোড করে কাজ শুরু করতে হয়।
*   **MCQ Point:** এই সেভ করা এবং লোড করার প্রক্রিয়াটিকেই **Context Switch** বলে। 
*   **Overhead:** Context switch এর সময়টা পুরোপুরি সিস্টেমের জন্য 'Overhead' বা অপচয়, কারণ এই সময়ে CPU কোনো দরকারি কাজ বা ইউজারের কাজ করে না, শুধু সেভ-লোডের কাজ করে।
