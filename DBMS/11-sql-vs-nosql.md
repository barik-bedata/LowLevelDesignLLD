# SQL বনাম NoSQL - সহজ বাংলায়

ডেটাবেস মূলত দুই ধরনের হয়: **SQL (Relational)** এবং **NoSQL (Non-relational)**। আপনার প্রজেক্টের জন্য কোনটি বেছে নেবেন, সেটি নির্ভর করে আপনার ডেটার ধরনের ওপর।

---

## ১. SQL ডেটাবেস (Relational Database)
SQL (Structured Query Language) ডেটাবেসগুলোতে ডেটাকে টেবিল (Table), সারি (Row) এবং কলাম (Column) আকারে রাখা হয়। 
> 💡 **সহজ উদাহরণ:** এটিকে আপনি একটি সুন্দর করে সাজানো **Excel Sheet** বা রেজিস্টার খাতার মতো ভাবতে পারেন। এখানে আগে থেকেই ঠিক করা থাকে যে কোন কলামে নাম বসবে, কোন কলামে বয়স বসবে।

* **বৈশিষ্ট্য:** 
  * এর একটি ফিক্সড বা কড়াকড়ি স্কিমা (Strict Schema) থাকে। নিয়মের বাইরে কিছু রাখা যায় না।
  * এটি **ACID** প্রোপার্টি মেনে চলে, তাই ডেটা ১০০% নির্ভুল ও কনসিস্টেন্ট থাকে।
  * এটি সাধারণত ভার্টিক্যালি স্কেল (Vertical Scaling) করতে হয় (সার্ভারের RAM/CPU বাড়াতে হয়)।
* **কখন ব্যবহার করবেন?** ব্যাংকিং সিস্টেম, ই-কমার্স বা যেখানে ডেটার সম্পর্ক (Relation) অনেক জটিল এবং নির্ভুলতা সবচেয়ে বেশি জরুরি।
* **উদাহরণ:** MySQL, PostgreSQL, Oracle.

---

## ২. NoSQL ডেটাবেস (Non-relational Database)
NoSQL-এ ডেটাকে টেবিল আকারে না রেখে ডকুমেন্ট, কী-ভ্যালু বা গ্রাফ আকারে রাখা হয়। 
> 💡 **সহজ উদাহরণ:** এটিকে আপনি একটি **MS Word Document** বা ফোল্ডারের মতো ভাবতে পারেন। এখানে কোনো ধরাবাঁধা নিয়ম নেই। আপনি চাইলে একজনের শুধু নাম রাখতে পারেন, আবার আরেকজনের নামের সাথে তার শখের তালিকাও যুক্ত করতে পারেন।

* **বৈশিষ্ট্য:**
  * এর কোনো ফিক্সড স্কিমা নেই (Flexible Schema)। যেকোনো সময় নতুন ফিল্ড যোগ করা যায়।
  * এটি সাধারণত **BASE** প্রোপার্টি মেনে চলে (ডেটা ১০০% নির্ভুল হওয়ার চেয়ে হাই-অ্যাভেইলেবিলিটিতে জোর দেয়)।
  * এটি খুব সহজেই হরিজন্টালি স্কেল (Horizontal Scaling) করা যায় (নতুন সার্ভার যোগ করে)।
* **কখন ব্যবহার করবেন?** সোশ্যাল মিডিয়া পোস্ট, রিয়েল-টাইম চ্যাট, বিশাল পরিমাণ আনস্ট্রাকচার্ড ডেটা (Big Data) বা যেখানে ডেটার স্ট্রাকচার বারবার পরিবর্তন হয়।
* **উদাহরণ:** MongoDB (Document), Redis (Key-Value), Cassandra (Column-family), Neo4j (Graph).

---

## একনজরে পার্থক্য

| বিষয় | SQL | NoSQL |
| :--- | :--- | :--- |
| **গঠন** | টেবিল, রো, কলাম (Table-based) | ডকুমেন্ট, কী-ভ্যালু, গ্রাফ ইত্যাদি |
| **স্কিমা** | ফিক্সড (আগে থেকে ঠিক করা) | ফ্লেক্সিবল (যেকোনো সময় বদলানো যায়) |
| **স্কেলিং** | মূলত Vertical (সার্ভার বড় করা) | মূলত Horizontal (সার্ভার বাড়ানো) |
| **গ্যারান্টি** | ACID (নির্ভুলতা) | BASE (অ্যাভেইলেবিলিটি) |
| **উদাহরণ** | MySQL, PostgreSQL | MongoDB, Redis |
